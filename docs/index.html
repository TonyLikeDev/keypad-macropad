A 4x4 keypad that runs anything on your PC

An Arduino Uno, a keypad and a short script. Change what any key does by editing one text file.

One key press, five hops

The Uno stays an ordinary Arduino. It only reports which key was pressed. Everything a key actually does lives on the PC.

  1. Keypad

    16 keys, 8 wires

    A matrix of rows and columns. Pressing a key connects one row wire to one column wire.

  2. Arduino Uno

    keypad.ino

    Scans the matrix and sends one letter, a to p, over USB serial at 9600 baud.

  3. Bridge

    bridge.py

    Reads the letter and presses Ctrl+Alt+Shift plus that letter, like a very odd keyboard.

  4. AutoHotkey

    keypad.ahk

    Catches the combination and runs the action written for that key.

  5. Your PC

    the result

    An app opens, a shortcut fires, the volume changes, a screenshot lands on the clipboard.

Eight wires, no resistors

The keypad's eight pins go to eight pins on the Uno. The Keypad library turns on the Uno's built-in pull-up resistors, so nothing else is needed.

  • Solid is rows, dashed is columnsPins 1 to 4 go to D9, D8, D7, D6. Pins 5 to 8 go to D5, D4, D3, D2.
  • Keep D0 and D1 emptyThe Uno uses them to talk to the USB chip. A wire there makes sketch uploads fail with "not in sync".
  • The printed labels follow the rowsS1 to S16 on the keypad map straight onto the letters a to p, which is how the code names the keys.

Change a key in one line

Every key already sends a unique combination. Pointing it at something new means editing a line of text and restarting the script. The Uno is never touched.

keypad.ahk; ^!+ means Ctrl+Alt+Shift. The letter is the key: S1 is a, S2 is b, up to S16 as p.
^!+b::Run "calc.exe"                    ; S2  calculator
^!+g::Tap "^z"                          ; S7  undo
^!+l::Tap "{Volume_Down 3}"             ; S12 volume down
bridge.pyREPEAT = "hl"  # keys that keep firing while held: S8 volume up, S12 volume down

Reload after an edit. Run start_keypad.cmd. It stops the old copies and starts fresh ones, so you can run it as often as you like.

Hold to repeat. The Uno sends an uppercase letter every 0.2 seconds once a key is held for 0.4 seconds. The bridge only acts on those repeats for keys listed in REPEAT, so holding Calculator does not open fifty calculators.

What went wrong, honestly

The first plan did not work. The second one did, and it ended up simpler.

  1. The plan: make the Uno a real USB keyboard

    The Uno has a second chip that handles USB. Reflash it with keyboard firmware and the board appears as a keyboard, with no PC software at all.

  2. The firmware had vanished

    The original download links are dead and the copies left online differ from each other and target an older chip. So the firmware was built from source for the Uno's ATmega16U2. It came to 3,826 bytes.

  3. The USB chip refused to enter flash mode

    Touching RESET to GND on its header should put it in DFU mode. Twice the chip reset (the COM port vanished and Windows played the unplug sound) but it came back as a normal Uno, and Windows never saw a flash-mode device. Nothing was written to the board.

  4. The pivot: leave the Uno alone

    The Uno sends a letter per key, a small Python script turns it into a key combination, and AutoHotkey runs the action. Same goal, nothing to flash, and the key map is a text file.

A wire in the wrong hole
With the keypad wired into D0 and D1, uploads failed with "programmer is not responding". Moving the wires to D9 through D2 fixed it.
Labels that are not a grid
The S numbers run along the electrical rows, not down the columns. Pressing the four corners showed S1 is a, S4 is d, S13 is m and S16 is p.
A variable that does not exist
AutoHotkey 2.0.30 has no A_LocalAppData, so the VS Code key would have shown a warning on every load. Validating the file caught it.
Screens are not all the same size
The screenshot key needed a DPI fix to capture the right pixels, and was tested on a 1920 x 1080 monitor and a 768 x 1366 portrait one.

Build your own

You need an Arduino Uno R3, a 4x4 membrane keypad, eight jumper wires, a USB cable and a Windows PC.

  1. Wire

    Connect keypad pins 1 to 8 to D9, D8, D7, D6, D5, D4, D3, D2, as in the diagram above.

  2. Upload

    Install the Keypad library and upload the sketch. Use your own port name in place of COM3.

    arduino-cli lib install Keypad
arduino-cli compile --upload -p COM3 --fqbn arduino:avr:uno keypad

  3. Install

    Get Python's serial library, then unzip the portable AutoHotkey v2 into tools\autohotkey.

    pip install pyserial

  4. Run

    Start the hotkey script and the bridge together. Press S2 and Calculator opens.

    start_keypad.cmd

Made with an Arduino Uno, the Keypad library, pyserial and AutoHotkey v2. The code is on GitHub.

Windows only: the bridge and the hotkey script use Windows features. The Uno sketch works anywhere.
